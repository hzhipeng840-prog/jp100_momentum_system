# v7

公開日: 2026-06-18

## 目的

GitHub Actionsの朝実行で、yfinanceが当日の未収盤日足を返した場合でも、
前営業日を対象にした日次更新を安定して完了できるようにする。

## 原因

2026-06-18 10:44 JSTのActions実行では、実行対象日は前営業日の `2026-06-17` だった。
一方でyfinanceの一部銘柄データには `2026-06-18` の日足行が含まれていたため、
パイプラインが取得基準日を `2026-06-18` と判定し、期待日不一致で失敗した。

## 変更

- `expected_trade_date` が指定されている場合、価格履歴を期待基準日までに切り詰める。
- その後に特徴量、Top100、毎日厳選、市場環境を計算する。
- 期待日より後の未収盤データは、クラウド日次更新では使用しない。

## 互換性

- 評価式、Top100、毎日厳選条件、CSV出力構造はv6から変更しない。
- ローカルで `expected_trade_date` を指定しない通常更新では、従来通り取得済みの最新日足を使う。
- GitHub Actionsでは前営業日や指定基準日を守るため、対象日より後の行を無視する。

## 検証

- 期待基準日より後の価格行を含む履歴でも、期待基準日でスナップショットを生成する
  回帰テストを追加。
- `app.py`、`daily_job.py`、`cloud_job.py`、`src`、`tests` の構文確認。
- オフライン単体テストを実行する。

## 既知の制限

- yfinanceが期待基準日そのものをまだ返していない場合は、v5と同様に `price_not_ready` として
  公開をスキップする。
- `^TOPX` など一部ティッカーの欠損警告は、基準日不一致とは別問題として残る場合がある。
