# v4

公開日: 2026-06-15

## 目的

日次更新を人のPC起動状態に依存させず、実行失敗を確認でき、
生成データとコード履歴を分離した形で継続運用できるようにする。

## 実行方式

- GitHub Actionsのネイティブスケジュールを使用する。
- 平日19:17（日本時間）を通常実行、21:47を補完実行とする。
- 最終的な営業日判定は `exchange_calendars` の `XTKS` で行う。
- 休場日と、同じ基準日・同じ版の完了済み実行は正常終了でスキップする。
- `workflow_dispatch` から手動実行と強制再実行ができる。

GitHub Actionsの定刻実行には混雑による遅延可能性がある。
本システムは日次終値ベースのため、分単位の厳密な起動よりも、
通常実行と補完実行の二段構成を優先する。

## 価格キャッシュ

- 銘柄別の日足CSVを `data/raw/prices/` に原子的に保存する。
- キャッシュが65営業日未満の銘柄は既定の1年分を取得する。
- 十分なキャッシュがある銘柄は直近10日分だけを取得し、日付で重複排除する。
- Actions Cacheは再取得量を減らす補助であり、正式な生成結果の保存先にはしない。

## 公開方式

- コード、設定、テストは `main` ブランチで管理する。
- 日次生成結果、累積履歴、最新スナップショットは `data` ブランチへ公開する。
- 日次更新によって `main` のコミット履歴を増やさない。
- 最初に成功したActions実行が `data` ブランチを作成する。
- 実行ログ、状態JSON、処理済みファイルはActions Artifactへ14日保存する。

## 基準日保護

クラウド実行日は日本時間の当日を期待基準日とする。
yfinanceから得た候補銘柄の最新基準日が期待日と一致しない場合、
履歴と公開結果を更新せず失敗する。19:17時点で無料データが未反映でも、
21:47の補完実行で再確認できる。

## ローカル同期

次のスクリプトで `origin/data` の履歴、処理済み結果、
最新スナップショットをローカルへ取り込む。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/sync_cloud_data.ps1
```

ローカルの基準日がクラウドより新しい場合は上書きを拒否する。
内容を確認した上で必要な場合だけ `-Force` を使用する。

## 互換性

- 評価式、重み、Top100、毎日厳選条件はv3から変更しない。
- 旧形式の絶対パスを持つ `latest.json` も引き続き読み込める。
- `data/processed/` の従来ミラーファイルを維持する。

## 既知の制限

- GitHub Actionsのスケジュールは指定時刻から遅延する場合がある。
- リポジトリやActionsが無効化された場合は自動更新されない。
- Actions Cacheは一定期間未使用の場合に削除され、次回は全量取得へ戻る。
- Yahoo!ファイナンスとyfinanceの仕様変更、遅延、欠損により更新が失敗する場合がある。
